# Paper 1.21.11 compatibility work (issue #1)

This branch introduces a Paper 1.21.11-specific implementation of the synthetic crafting inventory view and crafting event dispatch path. It is **not yet a verified release**. See [issue #1](https://github.com/ArmaRealms/ArmaSuperCraft/issues/1) and [PR #2](https://github.com/ArmaRealms/ArmaSuperCraft/pull/2).

## Build and compatibility

- Run the Gradle wrapper with **JDK 21**. CI config now requests Temurin 21.
- Kotlin 2.4.20 / Dagger 2.60.1 / GradleUp Shadow 9.6.1 / Gradle 9.8.1 are configured; dependency resolution and compilation remain to be confirmed.
- The `paper-1.21.11` module compiles against `io.papermc.paper:paper-api:1.21.11-R0.1-SNAPSHOT` as `compileOnly`.
- Legacy compatibility modules remain compiled for Java 8 bytecode. The `paper-1.21.11` module, its consuming `fastcraft-bukkit` aggregator, and the root plugin project now target Java 21 in **both** the Gradle Java variant attributes and Kotlin/JVM compilation.
- **The assembled plugin now requires Java 21 at runtime**, even when deployed on an older server. Maintaining a Java 8-compatible distribution requires a separate build/artifact that excludes the Paper 1.21.11 module.
- The `plugin.yml` API compatibility declaration was not raised to 1.21 because it would make older server versions reject the plugin; this does **not** make the new Java 21 JAR usable with a Java 8 runtime.

## Dagger / Kotlin metadata compatibility

- Dagger `2.52` could not process Kotlin 2.4 metadata (metadata version `2.4.0`, maximum supported version `2.1.0`).
- Dagger **2.60.1** contains the Kotlin 2.4 compatibility fixes shipped in the Dagger 2.60 line. Both `dagger` and `dagger-compiler` use the same `dagger_version` property, including kapt dependencies.
- Do not add a standalone `kotlin-metadata-jvm` dependency to work around the old processor: the fix belongs in the annotation processor itself.
- After upgrading, run `./gradlew clean assemble test`, then `./gradlew runServer` on Java 21; validate that Dagger-generated classes and the shaded JAR load normally. These commands are pending execution.

## Dagger 2.60 Jakarta runtime dependency

- Local `runServer` reached Paper **1.21.11 build 132**, loaded the FastCraft JAR and reached `onEnable()`, but activation failed with `NoClassDefFoundError: jakarta/inject/Provider` in `DaggerBukkitFastCraft_Factory`. The `onDisable()` callback then failed with a separate null dereference because `fastCraft` had never been assigned.
- Keep existing `javax.inject` dependencies for legacy modules. Dagger 2.60-generated components also reference **`jakarta.inject.Provider`**; the root project now explicitly depends on `jakarta.inject:jakarta.inject-api:2.0.1`. The Shadow allowlist includes it, the contents are relocated to `net.benwoodworth.fastcraft.lib.jakarta.inject`, and minimization excludes this API to retain generated-code dependencies.
- `BukkitFastCraft.onDisable()` now tolerates failure before `fastCraft` initialization, and the Bukkit version warning ignores the `-R0.1` API revision when comparing Minecraft release versions.
- `verifyShadedInjectionApi` checks **both** relocated `javax.inject.Provider` and `jakarta.inject.Provider` classes in the resulting JAR. `assemble` and `runServer` depend on this check.

Verify the packaging and retest startup with Java 21:

```bash
./gradlew clean assemble test
./gradlew verifyShadedInjectionApi
./gradlew runServer
```

This failure was observed in a real Paper run, **before** these fixes; a successful startup and in-game crafting smoke tests are still pending. Packaging checks do not prove Dagger can create the component at runtime.

## Running Paper directly from the IDE

The root project applies [jpenilla/run-paper](https://github.com/jpenilla/run-task) **3.1.0**, as in ArmaPlugins. Gradle 9.8.1 satisfies its Gradle 9.7+ minimum. The project's shaded JAR is built by the maintained [GradleUp Shadow](https://github.com/GradleUp/shadow) **9.6.1** fork (`com.gradleup.shadow`), replacing the obsolete `com.github.johnrengelman.shadow` plugin.

With **JDK 21** selected as the Gradle JVM, run the Gradle task `runServer` from IntelliJ IDEA, or execute:

```bash
./gradlew runServer
```

This downloads and launches **Paper 1.21.11** locally, builds and installs the root project's **shaded FastCraft plugin JAR** automatically, and starts the server with the same JVM flags as ArmaPlugins:

- `-Dcom.mojang.eula.agree=true` — accepts the Minecraft EULA for this local test run (review [Minecraft EULA](https://www.minecraft.net/en-us/eula) before running).
- `-Dnet.kyori.ansi.colorLevel=truecolor` — truecolor terminal support.
- `-Dfile.encoding=UTF8` — UTF-8 encoding.
- `terminal.jline=false` and `terminal.ansi=true` — terminal behavior for IDE consoles.

The development server files live under `run/` at the project root and are excluded by `.gitignore`. No external plugins are downloaded automatically; this task tests FastCraft on a clean Paper environment. Stop the server with `stop` in the console. All settings apply only to the local `runServer` task, not to production deployments.

## Gradle 9 migration notes

- Project build uses the Kotlin Gradle Plugin **2.4.20** and `compilerOptions` instead of the old `kotlinOptions` DSL; `buildSrc` uses the same Kotlin version.
- The deprecated Gradle Enterprise plugin was replaced with **Develocity 4.4.3**. Automatic Build Scan publication remains restricted to CI.
- Kotlin 2.4.20 officially lists Gradle support up to 9.7.0; newer Gradle builds are expected to run but may expose warnings or unsupported features. A full Gradle 9.8.1 build/test must be executed before declaring compatibility.
- Running with **Java 21** is required. Gradle 9 drops support for running the daemon on Java 8, and the unified plugin needs Java 21.
- This is a breaking build-tool upgrade; check Gradle and Kotlin deprecation warnings, the Shadow relocation/minimization output, and the shaded plugin's contents before deployment.

## Paper API registry bootstrap in tests

- Paper 1.21.11 initializes `InventoryType`, `MenuType`, `Registry` and `ItemStack` through `RegistryAccess`. Instantiating these without a server or a registry provider fails with `No RegistryAccess implementation found`, followed by misleading `NoClassDefFoundError` errors for already-failed static initializers.
- `CraftingInventoryViewFactory12111Test` runs under `MockBukkitExtension`, which boots and tears down a lightweight simulated Bukkit/Paper environment. MockK remains in use for exercising slot mappings, inventory iteration and holder delegation.
- `mockbukkit-v1.21:4.110.0` is a **test-only** dependency; it targets Paper API 1.21.11. The module's JUnit Jupiter is aligned to **6.0.3** to avoid mixing the JUnit 5 engine with MockBukkit's JUnit 6 API.
- **Do not suppress or skip these tests** to work around Paper registries. Use `./gradlew :fastcraft-bukkit:paper-1.21.11:test --rerun-tasks` and inspect all three test results. The server-side smoke test remains necessary.

## Modern crafting design

- Select the modern factory only for server versions >= 1.21.11.
- Do not instantiate old `InventoryView()` subclasses on modern Paper, where `InventoryView` is an interface.
- Dispatch prepare/craft events using a synthetic view that never opens a real crafting window.
- The 3x3 workbench matrix maps to raw slots **1 through 9**; raw slot **0** is the result.
- `CraftItemEvent` is sent using result slot **0**, rather than the former hard-coded **9**.
- GUI click handling avoids directly invoking `InventoryView` methods compiled against the old class ABI.
